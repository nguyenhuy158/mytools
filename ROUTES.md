# Routes Reference

Every URL this app answers, generated by reading `app/routes.ts` and
`workers/cli.ts` — not by memory. If you add, rename or remove a route,
update this file in the same change; `__tests__/routes/meta.test.ts` already
enforces that every page route has a `<title>`, but nothing enforces this
doc staying in sync.

Two request-routing layers exist:

1. **`workers/cli.ts`** runs first, inside the Worker `fetch` handler. It
   answers curl/wget-style clients with plain text and returns `null` for
   everything else, so it never shadows the routes below for a browser.
2. **`app/routes.ts`** (React Router) handles everything else: every page and
   every `/api/*` endpoint.

## API routes

All return JSON unless noted. None are documented elsewhere, so this is the
only reference for method, params and shape.

### `/api/notes`

Notes are scoped to an anonymous owner: the first request that has no
`notes_owner` cookie gets one minted (`httpOnly`, `Secure`, `SameSite=Lax`,
1-year `Max-Age`), and every note is created, listed, edited and deleted
under that owner only. See `app/utils/notes-owner.ts` and `BUGS.md` (S1) for
why. There is no login — clearing cookies or switching browser starts an
empty list.

| Method | Query/body | Behavior |
| --- | --- | --- |
| `GET` | `?search=<text>` (optional, matches title or plain text, case-insensitive) | Lists the caller's notes, newest `updatedAt` first. `plainText` is truncated to 100 chars. No cookie yet → `[]` plus a fresh `Set-Cookie`. |
| `POST` | form field `title` (defaults to "Untitled Note") | Creates an empty note owned by the caller, `201`. Mints an owner cookie if the caller has none. |

### `/api/notes/:id`

| Method | Body | Behavior |
| --- | --- | --- |
| `GET` | — | Returns the full note (`content`, `plainText`, etc). `404` if it doesn't exist **or belongs to another owner** — always the same error either way, so an id cannot be probed for existence. |
| `PUT` | form fields `title`, `content` | Updates the note; `content` is also re-derived into `plainText`. Same 404-for-not-yours rule. |
| `DELETE` | — | Deletes the note and removes it from the owner's list. Same 404-for-not-yours rule. |

### `/api/holidays`

`GET`, no params. Returns `{ holidays: Holiday[] }` parsed at request time from
`public/data/holidays-2026.csv` — solar and lunar Vietnamese holidays for
2026. `{ date, lunarDate?, name, type: "solar" | "lunar" }`.

### `/api/projects-status`

`GET`, no params, edge-cached (`s-maxage=300`). Pings every entry in
`app/data/projects.ts` and returns:

```json
{
  "checkedAt": "2026-...",
  "summary": { "total": 16, "checked": 15, "online": 15, "offline": 0, "medianMs": 168 },
  "statuses": [{ "id": "...", "online": true, "ms": 160, "httpStatus": 200 }]
}
```

The site's own hostname is answered as `{ online: true, ms: null, self: true }`
without a fetch — a Worker fetching its own zone loops back through
Cloudflare and 522s. A `52x` from another host **on the same Cloudflare
zone** (e.g. a sibling subdomain) is reported as `online: null` with an
`error` explaining the loopback, not as offline — see `app/routes/api.projects-status.tsx`
(`isSameHost`, `isSameZone`, `reconcileSameZone`).

### `/api/loto/create-room`

`POST`, no body. Creates a Durable Object room (`env.LOTO_ROOMS`) with a
random UUID and returns `{ success, roomId, wsUrl }`.

### `/api/loto/room/:roomId/ws`

WebSocket upgrade only — a plain HTTP request gets `400 Expected WebSocket`.
Forwards the upgrade to the named `LOTO_ROOMS` Durable Object instance.

### `/api/online-counter/ws`

WebSocket upgrade only, same `400` behavior for a plain request. Forwards to
a single global-named `ONLINE_COUNTER` Durable Object instance that tracks
how many browsers currently have the site open.

## CLI layer (`workers/cli.ts`)

Answers terminal clients (curl, wget, no `User-Agent` at all, or `?cli`)
directly from the Worker, before React Router ever sees the request. A
browser `User-Agent` still gets the normal HTML site at every path below.

| Path | Behavior |
| --- | --- |
| `/` | Short banner + case list, for a CLI client only. |
| `/<case>`, `/<case>/<text>`, `/<alias>` | Converts `<text>` (from the POST body, `?text=`, or trailing path segments) using one of `upper lower sentence capitalized title alternating inverse`, or its alias (`u uc l lc s c cap t a alt i inv`). `?json` replies with `{ mode, input, result }` instead of plain text. |
| `/-h`, `/--help`, `/help`, `/h`, `/usage` | Full usage text, any client. |
| `/sh`, `/shell` | A POSIX `sh` `tc` function to `eval`, so text needs no quoting. Prefers `curl`, falls back to `wget`. |

Full usage: `curl huyab.click/-h`. Implementation and the fall-through rule
that keeps every route above intact are covered by
`__tests__/workers/cli.test.ts`.

## Adding a route

- Register it in `app/routes.ts`.
- Give the route module its own `meta` export with a distinct `<title>` —
  `__tests__/routes/meta.test.ts` fails the build's test suite otherwise
  (only an `index()` route may inherit its layout's).
- Add a row to this file in the same change.
